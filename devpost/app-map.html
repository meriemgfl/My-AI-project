Why the pieces are split up

These boundaries make the feature easier to reason about and change.

The browser handles the interaction

src/App.jsx owns the visible screens and short-lived UI state. It asks the API to save or load; it does not write SQL.

The API owns the decision

server/index.js validates input and calls buildSuggestions(). Rebuilding on the server means the saved routine comes from the same rules as the shown suggestion.

The database keeps history

A routine has many ordered steps. Each step stores a product snapshot, so removing a product from your shelf does not erase what an older routine said to use.

3 · Follow the SQL model

saved_routines is the parent. routine_steps is the child table, with a step order and a JSON snapshot for each product.

Practice: read your saved steps with SQL

This joins each routine to its child rows and sorts the steps into the order the app displays them.

SELECT r.title, r.preferred_time, s.step_order, json_extract(s.product_snapshot_json, '$.name') AS product FROM saved_routines AS r JOIN routine_steps AS s ON s.routine_id = r.id ORDER BY r.id, s.step_order;

Carry the pattern into another app

This same parent-and-ordered-steps design could represent a project and its steps, a recipe and its instructions, or a film watchlist and viewing order. Keep the plan as one record, and its ordered parts as related records.

Scope: local, single-device proof of concept. Suggestions are rule-based catalog matches, not clinical advice. Catalog variants and product guidance should be checked against the exact packages before relying on them.
